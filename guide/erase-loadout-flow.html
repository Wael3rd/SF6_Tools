About the source files

The functions below come from Wael's private training suite (repo Wael3rd/SF6_REFramework, not public). They are not part of vanilla REFramework or any public mod.

  • RecordingManagerTab.lua — custom Lua module that adds the "Manager" tab (30 slots, loadouts) to the game's Recording Settings menu via native pause-menu injection.
  • NativePauseMenu.lua (PM) — custom Lua module that drives the game's own pause-menu rows: creates spins, buttons, and tabs by injecting TrainingMenuData into the game's TrainingMenuFunc system. PM.prepare_page() and PM.refresh_native_texts() are its API.
  • RSM (SF6_RecordingSlotManager) — custom Lua module that manages per-character recording slots (file I/O, virtual slots 9–30, naming). Exposed to RecordingManagerTab via rsm().

Engine-native (game code, not ours): TrainingMenuFunc.ViewUpdate, UpdateRecordSlotItem, UpdatePlaySlotItem, UIPartsGroupScroll.UpdateScroll. These are methods on the game's own managed types, called through REFramework's sdk.hook / :call.

Jumping a spin to a specific value

A spin's displayed value is controlled by three things that must stay in sync. Setting only one leaves the others stale — the game overwrites your change on the next focus or page build.

_ViewDataList[row].Index (+ .SliderValue)

What the game renders from. Lives on Param._ViewDataList at the spin's row index. The game copies UIPartsSpin._Num into Index on each D-pad press.

local param = 
local vd = param:get_field("_ViewDataList"):call("get_Item", row_index)
vd.Index = target
vd.SliderValue = target

Trap: the ViewData object handed to the Function(ftype, param, viewData, value) callback is NOT the same object as _ViewDataList[row]. Writes to the callback's ViewData are silently lost.

UIPartsSpin._Num

The part's internal value. The game re-initializes it via Init(min, max, num, action) at every page build and every focus, ignoring whatever ViewData says. To hold your value, hook Init and replace the num argument:

-- in the Init pre-hook:
args[5] = sdk.to_ptr(your_value)

Also hook set_Num for the brief window right after Init where the flow writes its own num back.

ScrollList.set_SelectedIndex (the carousel)

The via.gui.ScrollList inside the UIPartsSpin (p_ScrollList_0_h). This is the visual carousel — what the player sees.

local scroll_list = child_named(part:call("get_Control"), "p_ScrollList_0_h")
scroll_list:call("set_SelectedIndex", target_value)

-- The visible text (the game won't refresh it on its own)
local sel = child_named(scroll_list, "c_selectItem")
local txt = child_named(sel, "e_txt_0")
txt:call("set_Message", your_option_text)
Thread rule

The carousel writes (set_SelectedIndex, set_Message) must happen from the UI flow thread (e.g., in an UpdateSpinBox post-hook), never from LateUpdateBehavior — writing from there races the UI job thread and crashes the game in a text hash.

Complete sequence
-- All three, in order, from the UI flow thread:

-- 1. ViewData entry
local vd = param:get_field("_ViewDataList"):call("get_Item", row)
vd.Index = target;  vd.SliderValue = target

-- 2. Part's _Num
part:call("set_Num", target)

-- 3. Carousel visual
local scroll = child_named(part:call("get_Control"), "p_ScrollList_0_h")
scroll:call("set_SelectedIndex", target)
local txt = child_named(child_named(scroll, "c_selectItem"), "e_txt_0")
txt:call("set_Message", option_text)
