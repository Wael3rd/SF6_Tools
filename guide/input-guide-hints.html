SF6 Input Guide Hints

Comment modifier les textes de hint en bas de l'écran — REFramework Lua

Structure

Agent "InputGuide" (un par joueur sur l'écran VS) └─ UIPartsInputGuideList (part) └─ Control → c_guideBtn (conteneur) ├─ e_text_0 ← TEMPLATE (préfab, cloné par le moteur) ├─ e_text_0_d_0001 ← "Esc Retour" ├─ e_text_0_d_0002 ← "F Confirmer" ├─ e_text_0_d_0003 ← entrée clonée └─ e_text_0_g_0001 ← "Appliquer à tous"

Les entrées e_text_0_d_* sont des clones du template e_text_0, créés par app.UIPartsInputGuideBase.NewInputItem (6 surcharges). Le jeu les recrée à chaque changement d'écran ou de périphérique.

Lire un texte

local msg = text_element:call("get_Message")
-- msg contient du markup : "<ICON BtnD> Edit Color"

Modifier un texte

Méthode : suffixe (la plus sûre)

-- Lire le texte actuel du jeu
local cur = text_element:call("get_Message")

-- Ajouter notre hint (6 espaces = séparateur visuel)
local hint = cur .. "      <ICON BtnD> Mon Texte"

-- TOUJOURS comparer avant d'écrire (règle 15)
if tostring(text_element:call("get_Message")) ~= hint then
    text_element:call("set_Message", hint)
end

Quand écrire

Post-hook de OnLateUpdate uniquement. Le jeu réécrit les textes chaque frame dans ce callback. Écrire ailleurs = immédiatement écrasé.
local m = sdk.find_type_definition("app.UIPartsInputGuideList")
              :get_method("OnLateUpdate")
sdk.hook(m,
    function(args)
        -- pre: sauvegarder l'adresse pour filtrer
        thread.get_hook_storage()["my_igl"] = sdk.to_int64(args[2])
    end,
    function(rv)
        local addr = thread.get_hook_storage()["my_igl"]
        if addr == ma_part_addr then
            -- Le jeu vient de réécrire → on ajoute les nôtres
            guide_text_fix()
        end
        return rv
    end)

Template comme texte libre

ColorSpinExtra utilise le template e_text_0 (normalement invisible) comme texte positionné dans le coin :

local pos = template:call("get_Position")
template:call("set_Position", Vector3f.new(0, -980, pos.z))
template:call("set_Message", "X Couleur du Drive Impact")
PIÈGE CRITIQUE — Le moteur clone ce template pour fabriquer les entrées. Si le template est déplacé (y≠0) au moment du clone, la nouvelle entrée hérite de cette position et toute la barre saute.

Solution : hook pre/post sur les 6 surcharges de NewInputItem — baisser le template à y=0 dans le pre-hook, le remonter dans le post-hook :

local td = sdk.find_type_definition("app.UIPartsInputGuideBase")
for _, m in ipairs(td:get_methods()) do
    if m:get_name() == "NewInputItem" then
        sdk.hook(m,
            function()
                -- pre: template a y=0 pour que le clone parte bien
                template:call("set_Position", Vector3f.new(x, 0, z))
            end,
            function(rv)
                -- post: remonter le template
                template:call("set_Position", Vector3f.new(x, corner_y, z))
                return rv
            end)
    end
end

Règles anti-crash

1. JAMAIS Add / NewInputItem depuis Lua — pool fixe de contrôles. Item sans contrôle = crash UIPartsManager.get_AllParts (règle 13).
2. JAMAIS set_Message avec un texte identique — crash UIPartsItem.UpdateFocus (règle 15). Toujours comparer avant.
3. JAMAIS toucher le template d'un autre joueur — 2 barres sur l'écran 2J. Template de P2 corrompu → crash 0x2d419f3.
4. Écrire UNIQUEMENT depuis le post-hook de OnLateUpdate ou LateUpdateBehavior.
5. Remettre les textes d'origine en quittant — sinon le suffixe reste sur les autres écrans.
