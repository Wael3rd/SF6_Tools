Bottom-Screen Hint Texts

How the two text lines at the bottom of SF6 training menus work, and how to set them from Lua.

The two lines

What you see at the bottom of the training pause menu

Line 1 — Description text (white/yellow): changes per focused row.
Example: "Browse and download loadouts shared by others."

Line 2 — Input guide bar (icons + labels): shows available buttons.
Example: F Confirm    Esc Back    A + E Return to General tab

Line 1 is the guide parameter you pass when creating a menu row. Line 2 is built automatically by the game's InputGuide agent.

Line 1 — Description text

Setting it via NativePauseMenu

Every row-creation method takes a guide string as its second argument. This is the description shown at the bottom when that row is focused:

local PM = require("func/NativePauseMenu")

-- Simple row on the main SF6 Tools tab
PM.spin("My Setting", "Adjust this value to change X.", {"Low", "Medium", "High"}, get_fn, set_fn)
PM.button("Do Something", "Press confirm to trigger the action.", on_decide_fn)

-- Custom tab with its own page
local pg = PM.page("My Tab", "Description shown when the tab header is focused.")
pg:spin("Speed", "How fast it goes.", {"1x","2x","4x"}, get, set)
pg:button("Reset", "Reset all settings to defaults.", reset_fn)
pg:toggle("Enabled", "Turn this feature on or off.", get, set)
pg:number("Distance", "Target distance in game units.", 0, 500, 10, get, set)
pg:value("Status", "Current status (read-only).", status_fn)
pg:label("Info Line", "This row is not interactive.")

All row types

MethodArgsDescription
:spin(title, guide, options, get, set)options: table or functionLeft/right selector

Dynamic descriptions

The guide can be a function instead of a string. It will be called each time the menu rebuilds or the row is focused:

pg:spin("Slot", function() return "Currently loaded: " .. current_slot_name() end,
    slot_options, get_slot, set_slot)

How it works internally

NativePauseMenu converts the guide string into a message GUID via NativeOptions.message_guid(text), then writes it to the _GuideMessage field of the row's TrainingMenuData. The game reads this GUID when the row gains focus and displays the resolved text at the bottom.

-- What NativePauseMenu does under the hood (you don't call this):
item.guide_guid = NO.message_guid(text_of(item.guide))
NO.set_guid(data, "_GuideMessage", item.guide_guid)

Line 2 — Input guide bar

The button hints bar (F Confirm · Esc Back · A+E Switch tab) is drawn by the game's InputGuide agent automatically. The game decides which buttons to show based on the current menu context.

Structure

Agent "InputGuide" └─ UIPartsInputGuideList (part) └─ Control → c_guideBtn ├─ e_text_0 ← TEMPLATE (cloned by NewInputItem) ├─ e_text_0_d_0001 ← "F Confirm" ├─ e_text_0_d_0002 ← "Esc Back" └─ e_text_0_d_0003 ← "A + E Switch tab"

Appending a custom hint

You cannot add new entries (crash — fixed pool of controls). Instead, append to an existing entry's text in the post-hook of OnLateUpdate:

local m = sdk.find_type_definition("app.UIPartsInputGuideList")
              :get_method("OnLateUpdate")
sdk.hook(m,
    function(args)
        thread.get_hook_storage()["igl"] = sdk.to_int64(args[2])
    end,
    function(rv)
        local addr = thread.get_hook_storage()["igl"]
        if addr ~= my_part_addr then return rv end
        -- Read current text, append our hint
        local cur = tostring(text:call("get_Message"))
        local want = cur .. "      <ICON BtnD> My Action"
        -- ALWAYS compare before writing (rule 15)
        if tostring(text:call("get_Message")) ~= want then
            text:call("set_Message", want)
        end
        return rv
    end)

Using the template as a free-positioned text

The template e_text_0 is never shown by the game. ColorSpinExtra repurposes it as a floating text in the top-left corner:

template:call("set_Position", Vector3f.new(0, -980, 0))
template:call("set_Message", "X Drive Impact Color")
Clone trap — The engine clones e_text_0 to build entries. If the template is at y≠0 during the clone, the new entry inherits that position and the whole bar jumps. Fix: hook all 6 overloads of NewInputItem, set y=0 in pre-hook, restore in post-hook.

Rules (each one crashed the game)

1. Never call Add or NewInputItem from Lua — the prefab has a fixed pool of controls. An item without a control crashes UIPartsManager.get_AllParts.
2. Never set_Message with an identical string — crashes UIPartsItem.UpdateFocus. Always compare get_Message first.
3. Never touch another player's template — two guide bars exist on the 2-player screen. Writing to P2's template when you don't own it corrupts the clone model → crash 0x2d419f3.
4. Write only from the OnLateUpdate post-hook or LateUpdateBehavior — the game rewrites every frame; other timings are overwritten.
5. Restore original texts when leaving — otherwise the suffix leaks to other screens.
